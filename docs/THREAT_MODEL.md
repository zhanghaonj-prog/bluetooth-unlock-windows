# Bluetooth Unlock 威胁模型

状态：开源 P0 基线。本文描述当前设计和公开发布前必须处理的风险，不构成安全保证。

## 1. 保护资产

- 用户真实 Windows 登录密码及 DPAPI 密文。
- Windows 登录会话和桌面访问权限。
- Broker 一次性授权、锁屏周期和会话标识。
- 可信 Agent 路径与 SHA-256。
- 用户 BLE 标识、网络名称、日志和诊断数据。
- 安装包、更新渠道和代码签名密钥。

## 2. 信任边界

```text
附近无线环境
  -> 用户会话 Agent
  -> Agent 命名管道
  -> LocalSystem Broker
  -> Provider 命名管道
  -> LogonUI Credential Provider
  -> Windows LSA
```

Agent 所在用户会话不是高权限边界。Broker 以 LocalSystem 运行并持有解密凭据的能力；
Provider 运行在 LogonUI 安全桌面，是最敏感的可用性边界。

## 3. 攻击者模型

- 附近攻击者：模拟或重放 BLE 广播，尝试满足在场条件。
- 本机普通用户或恶意进程：连接管道、伪造 Agent、读取用户配置或制造输入事件。
- 其他 Windows 会话：尝试消费不属于自己的自动解锁授权。
- 本机管理员或 SYSTEM：读取 DPAPI LocalMachine 密文并解密密码。
- 供应链攻击者：替换安装包、Agent、Broker、Provider 或构建依赖。
- 误操作用户：登记 PIN 而非密码、密码过期后重复提交、删除 DLL 导致登录链路异常。

不承诺防御已取得管理员或 SYSTEM 权限的攻击者。DPAPI LocalMachine 只能提高静态存储
门槛，不能对管理员隐藏密码。

## 4. 主要威胁与控制

| 威胁 | 当前控制 | 剩余风险/计划 |
| --- | --- | --- |
| BLE 广播伪造 | 手表模式、RSSI、手机组合、离开再靠近 | 不是密码学认证；文档必须明确 |
| 非白名单场所触发 | Profile/SSID 白名单，授权前强制刷新 | 网络名称可被仿冒，不能作为身份因素 |
| 跨会话消费 | SID、SessionId、LockCycleId 绑定 | 继续补充多会话和快速用户切换测试 |
| 授权重放 | 短 TTL、每锁屏周期一次、事务消费 | TTL 应改用单调时钟 |
| 伪造 Agent | Broker 校验路径和 SHA-256 | 升级必须刷新哈希；需签名校验 |
| Provider 管道抢占 | SYSTEM 专用 ACL、固定管道名 | Provider 仍需验证服务端身份和 PID |
| LogonUI 阻塞 | 管道实例等待超时 | 连接后读写需要整体截止时间 |
| 凭据文件泄露 | DPAPI LocalMachine、SYSTEM/管理员 ACL | 管理员可解密；必须明确风险 |
| 密码错误反复提交 | 每锁屏周期有限尝试 | 增加失败熔断、账户锁定保护 |
| 日志泄露 | 普通日志不记录密码 | 增加 ACL、轮转和诊断脱敏 |
| 二进制篡改 | 发布清单和 SHA-256 | 公开发布前增加 Authenticode 和 CI 来源证明 |
| 卸载破坏登录 | 先撤销注册再删除 DLL | 增加 VM 故障注入和离线恢复演练 |

## 5. 安全定位

自动解锁是便利能力，不是以下任何一种：

- 第二因素认证。
- Windows Hello 的替代实现。
- 企业无密码认证。
- 可抵御本机管理员的凭据保险库。
- 对 BLE 中继、模拟或高增益攻击的可靠防护。

不建议在共享终端、域策略严格的企业设备、受监管系统或无法保留备用管理员账户的设备
上启用自动解锁。

## 6. 高风险失败模式

### 凭据错误

错误密码可能显示“用户名或密码不正确”并触发账户锁定策略。公开版本应在一次明确认证
失败后停止自动提交，要求手工登录并重新登记。

### Provider/Broker 不一致

手工覆盖二进制会导致可信 Agent 哈希失效；只复制 Provider DLL 可能留下无效 COM 注册。
升级和卸载必须通过安装器事务执行。

### 管道阻塞

Provider 的调用发生在 LogonUI 路径。任何无界等待都可能影响登录界面，应对连接、写入、
读取和事件线程退出设置统一截止时间，并在超时后安全返回“无凭据”。

### 公开供应链

未签名安装包可能被 SmartScreen 拦截，也无法让用户区分官方构建与篡改版本。公开 Beta
前至少签名安装程序、Agent、Broker 和 Provider。

## 7. 发布安全门槛

- 不包含真实配置、标识、日志、转储或凭据。
- Provider 验证 Broker 服务端身份。
- Provider 所有管道 I/O 有整体截止时间。
- 密码错误后自动熔断，且手工登录始终可用。
- 安装、升级、卸载和离线恢复完成故障注入测试。
- 二进制签名并公布 SHA-256 和 SBOM。
- `SECURITY.md` 提供私密报告渠道和支持版本。
- 完成至少一次独立代码审查和 Windows 10/11 登录回退验证。

## 8. 漏洞响应原则

高危范围包括凭据泄露、任意会话解锁、Provider 导致无法登录、非管理员修改 Broker 信任
配置和官方安装包被替换。收到报告后应先私下确认、限制受影响 Release、发布禁用/卸载
步骤，再修复和披露；不要要求报告者在公开 Issue 中提交日志或凭据。
